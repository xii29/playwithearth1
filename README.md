# Example Lab

브라우저에서 실행되는 인터랙티브 예제 모음입니다. 각 예제는 상단 메뉴에서 전환되며, 카메라 예제는 전환 또는 페이지 종료 시 자신의 스트림과 MediaPipe 인식기를 해제합니다.

## Aquarium

`Aquarium`은 전체 화면 카메라 영상을 몽환적인 수중 공간으로 바꾸는 얼굴·손 트래킹 예제입니다. 기본 상태에서는 열대어 캐릭터들이 자유롭게 유영하고, MediaPipe Face Landmarker의 `eyeLookOutLeft` 또는 `eyeLookOutRight` 값이 임계값을 넘으면 바라보는 쪽으로 물고기 무리가 모입니다. Hand Landmarker로 인식한 열 손가락 끝을 물고기 가까이 가져가면 주변 물고기가 사방으로 빠르게 흩어집니다. `jawOpen` 값으로 입을 벌린 상태를 감지하면 모든 물고기가 화면 밖으로 도망가고, 입을 닫으면 각자의 위치로 다시 헤엄쳐 들어옵니다.

## Sniper

`Sniper`는 얼굴 동작만으로 플레이하는 움직이는 과녁 게임입니다. `eyeBlinkLeft`와 `eyeBlinkRight` 중 한쪽 눈만 잠시 감으면 조준경이 활성화됩니다. 카메라 시작 시 보정한 정면 자세와 얼굴 랜드마크를 비교해 고개의 상하좌우 방향으로 조준점을 움직이고, 두 눈을 다시 뜨는 순간 자동으로 발사합니다. 과녁 중심의 검정 원은 100점이며 바깥쪽으로 80·60·40·20점 순서로 낮아지고, 과녁 밖은 0점입니다.

## DoodleFace

`DoodleFace`는 한 PC와 한 카메라 앞에서 두 사람이 함께 하는 로컬 게임입니다. 네트워크, 방 서버, WebRTC, WebSocket 또는 SSE를 사용하지 않습니다.

1. 두 사람이 카메라 앞에 나란히 섭니다.
2. 좌·우 얼굴이 약 650ms 동안 안정적으로 인식되면 5초 카운트다운이 시작됩니다.
3. 두 카메라 패널이 850ms 동안 서로 미끄러져 교환된 뒤 60초 라운드가 시작됩니다.
4. 색상을 고르고 엄지와 검지를 Pinch하면 상대 화면의 얼굴에 붙는 낙서를 남길 수 있습니다.

`public/mediapipe`에는 공통 로컬 WASM과 인식 모델이 있습니다. 선택한 카메라 예제에서 필요한 파일만 같은 서버로부터 로드하며 외부 CDN에 의존하지 않습니다. DoodleFace의 GPU 초기화가 실패하면 CPU delegate로 한 번 재시도합니다.

## 확인

```bash
npm run build
```

카메라 권한이 가능한 브라우저에서는 `#doodle`로 열어 로비, 도움말, 카메라 시작, 2분할 캔버스를 확인할 수 있습니다.

## 로컬 네트워크 HTTPS 개발 서버

현재 개발 인증서는 `localhost`, `127.0.0.1`, `::1`, `172.30.1.47`에 대해 발급되어 있습니다. 인증서와 개인 키는 `public`이 아닌 `.cert/`에 있으며 Git에서 제외됩니다.

```bash
npm run dev
```

같은 로컬 네트워크의 다른 기기에서는 Vite가 출력하는 `https://172.30.1.47:5173/` 주소로 접속합니다. 접속이 되지 않으면 두 기기가 같은 네트워크인지 확인하고 macOS 방화벽에서 Node/Vite의 5173 포트 인바운드 연결을 허용합니다.

다른 기기에서 인증서 경고 없이 카메라를 사용하려면 개발 PC의 `~/Library/Application Support/mkcert/rootCA.pem` 파일만 안전하게 전달해 해당 기기의 신뢰할 수 있는 루트 인증 기관으로 설치해야 합니다. `rootCA-key.pem`은 절대 공유하지 않습니다. 루트 CA를 설치한 뒤 브라우저를 완전히 다시 열고 사이트의 카메라 권한을 허용합니다. 단순히 인증서 경고를 우회하면 브라우저가 보안 컨텍스트로 인정하지 않아 카메라가 계속 차단될 수 있습니다.

로컬 IP가 변경되면 새 IP를 포함해 인증서를 다시 발급해야 합니다.

## 로딩과 예제 격리

- 선택한 예제만 지연 로딩·실행합니다. 같은 메뉴를 다시 눌러 불필요하게 재시작하지 않습니다.
- 빌드 HTML에서 현재 URL의 예제 모듈과 정적 의존성만 `modulepreload`로 먼저 요청합니다. 개발 서버는 Vite 기본 모듈 로딩을 사용해 의존성 최적화/HMR과의 중복 요청을 피합니다. 다른 예제나 카메라 모델을 미리 실행하지 않습니다.
- Chrome/Chromium의 마우스 예제는 CPU 기반 2D Canvas에서 동일한 별·그림자를 그려, 다수의 흐림 그림자를 GPU Canvas로 그릴 때 빈 프레임이 나오는 문제를 피합니다. OffscreenCanvas 작업 스레드가 완성된 ImageBitmap을 화면으로 전달하고, 표시 확인 후 다음 프레임을 그려 대기열을 제한합니다. 미지원/초기화 실패 시 일반 Canvas로 복구합니다. 예제 전환 시 작업 스레드를 종료하고, 숨긴 탭에서는 렌더링을 중지합니다. Safari는 기존 Canvas 렌더링 경로를 유지합니다.
- Chrome의 일반 Canvas 복구 경로는 프레임 사이에 16ms를 양보해 메뉴 입력이 막히지 않도록 합니다. 이 예외 경로는 정상 작업 스레드 경로보다 프레임 속도가 낮아질 수 있지만 별 개수·해상도·빛 번짐은 유지합니다.
- 빌드 미리보기의 콘텐츠 해시가 붙은 JS/CSS는 장기 캐시합니다. 수정 시 파일명이 달라지므로 새 빌드가 반영됩니다. 모델 파일은 기존 ETag 재검증을 유지합니다.
- 마우스·Aquarium 배경 그라데이션은 크기/상태별로 재사용하고, 인형뽑기의 고정 부품은 로컬 좌표 행렬 재계산을 생략합니다. 해상도, 입자 수, 그림자 및 애니메이션 속도는 낮추지 않습니다.
- 예제 전환 시 이전 예제와 공통 촬영 기능을 종료합니다. 진행 중인 공통 녹화는 전환 시 취소되므로, 저장하려면 먼저 녹화를 종료해 주세요.
- 페이지 복원 시 활성 예제를 다시 초기화합니다. 늦게 완료된 카메라 요청과 모델은 종료 상태를 확인해 정리합니다.
- 개발 서버는 공통 진입 파일을 미리 변환하며, 모델·WASM은 무손실 gzip 압축과 ETag 재검증을 사용합니다. 캐시는 파일 변경 시 갱신됩니다.
- Chrome/Safari의 실행 엔진·권한·인증서·기기 차이로 동일한 로딩 시간을 보장하지는 않습니다.

다른 PC에 완성된 예제를 공유할 때는 개발 중 변환 비용이 없는 빌드 미리보기도 사용할 수 있습니다. 기존 개발 서버 설정은 유지됩니다.

```bash
npm run build
npm run preview
```

미리보기 Network 주소는 `https://인증서에-포함된-로컬IP:4173/`이며 기존 개발 인증서를 사용합니다. `/#earth`, `/#aquarium`처럼 예제 해시를 붙이면 해당 예제로 바로 진입합니다. Vite preview는 로컬 확인용이며 운영 서버 용도가 아닙니다.

서버를 실행하지 않고 전송 동작을 확인하려면 `node scripts/check-lan-assets.mjs`를 실행합니다.

## 첫 화면 갤러리

기본 주소 또는 `/#home`은 흰 배경의 전체 번호 원형 메뉴입니다. 실 예제 17개와 빈 슬롯 15개, 총 32개 항목을 고정된 번호로 한 화면에 배치하며 항목이 늘면 번호도 자동 추가됩니다. 시침·분침은 없습니다. 스크롤·스와이프·방향키·하단 화살표로 회전하면 다음 선택 번호가 커집니다. 번호와 예제 연결은 회전해도 바뀌지 않습니다.

스크롤 선택·호버·키보드 초점 시 숫자가 커지고, 가운데에는 해당 예제 이름만 표시됩니다. 썸네일은 표시하지 않습니다. 숫자 또는 중앙 이름 클릭 시 바깥으로 퍼지는 페이드 전환 후 예제를 엽니다. 빈 슬롯은 실행되지 않습니다. 모션 감소 설정과 뒤로가기를 지원합니다.

갤러리는 카메라·AI 모델·3D 엔진을 불러오지 않습니다. 번호는 transform으로만 이동하며 화면 크기 변경 때만 배치 반경과 글자 크기를 계산합니다. 움직임이 수렴하면 프레임 요청을 멈추고, 숨겨진 탭 및 예제 전환 시 애니메이션·이벤트·관찰자를 정리합니다. 모션 감소 설정에서는 이동 전환 없이 즉시 갱신합니다.

`npm run build` 후 Playwright 환경에서 `node scripts/check-gallery.mjs`로 로딩 격리, 스크롤·시점 회전, 정지 상태 프레임 중단, 대표 이미지 선택, 반응형 배치, 예제 진입·복귀를 확인할 수 있습니다. 서버는 실행하지 않으며 필요하면 `PLAYWRIGHT_MODULE`과 `CHROME_PATH`로 설치 경로를 지정합니다.

## 카메라 효과 보정

### MONEY RAIN

`#money`는 전신 분할 마스크와 양손 관절을 이용한 지폐 인터랙션입니다. 사람이 인식되면 머리 위에서 가상 지폐가 떨어지고, 머리·어깨·팔 표면에 부딪히거나 미끄러진 뒤 화면 하단에 쌓입니다. 검지·중지를 펼친 V(나머지 손가락은 접음) 또는 가까이 모은 양손은 돈을 받는 면을 만듭니다. 잡은 지폐는 손을 따라 움직이며 동작을 풀면 다시 떨어집니다.

분할 마스크 격자에서 작은 이동 단위로 충돌을 검사하고, 동적으로 관통한 지폐를 신체 밖으로 보정합니다. 최대 320개 이동 지폐와 64개 바닥 축적 구간을 사용하고, 모의 지폐 이미지는 한 번만 그려 재사용합니다. 실제 강체 시뮬레이션이 아닌 경량 2D 충돌이며 손 가림·인식 오차로 받기/충돌이 달라질 수 있습니다. ‘돈 비우기’로 초기화합니다. `scripts/check-money-rain.mjs`에서 충돌·바닥 축적·손 이동 및 해제를 검사합니다.

## GitHub Pages 자동 배포

현재 저장소: `xii29/playwithearth1` · 기본 브랜치: `main`.
배포 후 주소: **https://xii29.github.io/playwithearth1/** (`#earth`, `#body-fx` 등 예제 직접 링크도 유지).

1. GitHub 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
2. 저장소 Actions가 비활성화되어 있으면 활성화합니다. 조직 정책이 있다면 워크플로에서 쓰는 GitHub 공식 Actions 사용을 허용해야 합니다.
3. 변경 파일을 커밋하고 `main`으로 push합니다. **Actions → Deploy to GitHub Pages**에서 성공 여부를 확인합니다. 이후 `main` push마다 자동 배포됩니다. 첫 수동 배포는 **Run workflow → main**을 선택합니다.
4. Pages 화면에서 표시되는 실제 배포 URL을 엽니다. 가능하면 **Enforce HTTPS**를 활성화하고, 브라우저에서 카메라/마이크 사용을 허용합니다. 로컬 mkcert 인증서는 GitHub Pages에 설치하지 않습니다.

`.github/workflows/deploy-pages.yml`이 Node 22에서 `npm ci` → 빌드 → 배포 파일 검사 → `dist` 업로드/배포를 수행합니다. 별도 PAT/Secrets나 `gh-pages` 브랜치는 필요 없습니다. Pages는 미리 활성화해야 하며, 비공개 저장소는 계정 요금제의 Pages 지원 여부를 확인하세요. `github-pages` 환경에 승인 규칙이 있으면 배포를 승인해야 합니다.

Pages가 알려주는 `base_path`를 `PAGES_BASE_PATH`로 전달하므로 저장소 이름 변경/루트 사이트/커스텀 도메인에도 대응합니다. 로컬 개발은 `/` 및 기존 LAN HTTPS 설정을 유지합니다. 인증서·비밀키·node_modules는 업로드하지 않고 `dist`만 배포합니다. `public`의 파일은 모두 공개되므로 개인 사진과 공개 권한이 없는 자료는 push 전에 확인하세요. 주민 저장 데이터는 브라우저와 접속 주소별로 저장되므로 로컬 주소의 데이터가 배포 주소로 자동 이전되지는 않습니다.

로컬에서 배포용 빌드 검사(서버 실행 불필요):

```sh
PAGES_BASE_PATH=/playwithearth1/ npm run build
PAGES_BASE_PATH=/playwithearth1/ node scripts/check-pages.mjs
```

일반 로컬 빌드는 `npm run build`입니다. 기본 경로 빌드와 하위 경로 빌드를 각각 확인했습니다. GitHub에 push/실제 배포는 별도로 진행해야 합니다.

### BODY POINT CLOUD · 작은 흰색 입자

`#body-fx`는 초기 스타일인 검은 배경과 작은 흰색 입자로 얼굴·몸 내부 전체를 표현합니다. 카메라 영상 자체는 표시하지 않고 명암만 입자의 밝기에 사용합니다. 화면과 마스크는 동일한 cover 좌표를 사용합니다. 리퀴드 투명화/배경 저장/손짓 제어 UI는 제거했습니다.

몸 영역과 명암의 프레임 간 변화를 이용해 일부 입자에 방향성 있는 잔상을 더합니다. 주요 입자는 실루엣에 고정해 사람 형태를 유지하고, 잔상은 시간이 지나면 감쇠하여 영구적으로 남지 않습니다. 별도 준비 동작 없이 카메라 권한을 허용하면 시작합니다.

전용 지연 로딩 모듈은 몸 분할 모델 하나만 사용합니다(손 모델 불필요). 약 18,000/32,000개의 재사용 입자 슬롯으로 밀도를 높이고, 잔상 참여 입자를 1/4에서 1/2로 늘렸습니다. 이동량을 약 2배 확대하고 5단계 꼬리와 느린 감쇠로 긴 잔상을 만듭니다. 8단계 묶음 그리기, 렌더 30fps, 인식 약 8~12fps, DPR 1.5 제한을 적용합니다. 비활성 탭과 카메라 중지 시 렌더를 멈추고 예제 종료 시 스트림/모델/이벤트를 정리합니다. `scripts/check-body-cloud.mjs`는 모의 카메라 기반으로 흑백 입자/실루엣 내부 채움/잔상과 소멸/손 모델 미사용/자원 해제를 검사합니다. 실제 카메라 인식 품질과 기기 발열은 별도 확인이 필요합니다.

### 18. AFTERGLOW · 손끝 불꽃놀이

`#afterglow`로 열 수 있습니다. 검정 배경에 꽃송이·링·황금 버드나무·하트·스파이럴 또는 랜덤 불꽃을 생성합니다. 검지를 원하는 곳에 약 0.65초 멈추거나 검지·엄지를 집어 생성하며, 클릭/터치도 지원합니다. 우측 ‘불꽃놀이 설정’ 패널은 접기/펼치기, 종류 선택, 전체 지우기를 제공합니다. 사람 마스크로 불꽃을 지워 몸 뒤에서 터지는 듯한 가림을 만듭니다(실제 3D 깊이 추정은 아님). 카메라 권한이 필요하며 원본 카메라 영상은 표시하지 않습니다.

불꽃 입자 최대 2,000개, 렌더 표면 최대 긴 변 1,280px, 30fps 제한을 적용하고 손·몸 추론은 같은 프레임에 중복 실행하지 않습니다. 모의 브라우저 테스트에서 전 종류 렌더/사람 영역 가림/클릭 생성/패널 접기 및 모델 해제를 확인합니다.

Money Rain은 초기 낙하 속도 8→10, 중력 35→44, 최대 속도 65→80으로 약 25% 빠르게 조정했습니다. 충돌 세부 스텝은 유지하고 손별 수량 계산 버퍼를 재사용하여 프레임별 할당을 줄였습니다.

### 동물의 숲 · 우주 에디션 (기존 Earth Village)

주민 대화창은 참고 이미지의 크림색 말풍선, 주황색 이름표와 하단 화살표 디자인을 적용했습니다. 주민을 따라보는 동작과 대화 입력·전체 보기·이름 변경·텍스처 편집 기능은 유지합니다. CSS 도형만 사용해 추가 이미지/3D 렌더 비용이나 반복 애니메이션이 없습니다. `scripts/check-resident-dialogue.mjs`는 실제 스타일의 데스크톱/모바일 배치와 제어 표시를 검사합니다.

갤러리 이름은 **동물의 숲**, 기존 링크는 `#earth`로 유지합니다. 좌측 로고는 사용자가 제공한 `public/logo.webp` 원본을 비율 유지하여 표시합니다. 별 배경, 보랏빛·청록빛 숲과 UI는 자체 제작한 우주 테마이며 캐릭터와 음악도 자체 생성합니다. 처음 열면 토끼·곰·고양이 계열의 기본 동물 주민 6명이 생깁니다. 저장된 마을이 있으면 그 주민들을 복원하며, 모든 주민을 방출한 빈 마을에도 기본 주민을 재생성하지 않습니다.

하단 **입주하기** → 이름 입력 → 왼쪽 카메라 / 오른쪽 이미지 업로드(클릭·드롭) → 이미지와 카메라 준비 후 5초 카운트 → 자동 촬영 → 중앙 미리보기 → 축소 입주 순서입니다. 이름이 비어 있으면 자동 이름을 사용하며 이후 변경할 수 있습니다. 기본 동물을 포함해 최대 24명의 주민이 지형 위를 걷고 서로를 피합니다.

- 주민 클릭 또는 좌측 주민 선택: 부드러운 추적 카메라와 대화창. 대화는 로컬 키워드·주민별 반응이며 외부 AI는 연결하지 않았습니다. **전체 보기**로 추적을 끝냅니다.
- 주민을 누른 채 드래그: 땅 위로 이동합니다. 나무·물 위의 드롭은 원위치로 돌아갑니다. **방출 구덩이** 안에 놓으면 축소되어 사라지고 저장 목록에서도 제거됩니다. 드롭 전 경고가 표시됩니다.
- **주민 회의**: 주민들이 공터로 둥실 이동해 모입니다. **회의 해산**으로 산책을 재개합니다.
- **텍스처 문지르기**: 사진 위를 색상·크기 브러시로 문질러 수정합니다. 원본 복원 브러시·되돌리기·전체 원본 복원을 지원하고 3D 캐릭터에 즉시 반영됩니다.
- 주민 이름·형체·현재/원본 텍스처·위치는 IndexedDB에 저장합니다. 같은 브라우저 프로필과 같은 출처(프로토콜·주소·포트)에서 다시 열면 복원됩니다. 브라우저 데이터 삭제, 시크릿 모드, 저장 용량 제한에는 영구 보존을 보장하지 않습니다. 사진은 외부로 전송하지 않습니다.
- 무작위 우주선 이벤트: 접근 → 착륙 → 우주인 3명 하선 → 별빛 광선 공격 → 출발. 공격받은 주민은 잠시 달아나며 영구 삭제되지 않습니다. 회의·드래그·텍스처 편집·입주 중에는 이벤트 시간을 멈춥니다.
- **♫ 음악 켜기**: 로컬 Web Audio로 자체 생성한 느린 펜타토닉 멜로디·베이스·화음을 재생합니다. 기존 게임 곡을 복제하지 않습니다. 탭을 숨기면 음악이 일시 중지되고 예제를 나가면 오디오와 예약 타이머를 정리합니다.

업로드한 단일 형체의 윤곽을 부풀린 메시로 만들고 상체가 크고 하체가 짧은 비율로 맞춥니다. **의미 기반 사물 인식이나 생성형 이미지→3D 서비스가 아니라 로컬 윤곽 기반 프로토타입**이므로, 복잡한 배경·여러 형체·가려진 뒷면은 정확히 복원하지 못합니다. 투명/단색 배경의 단일 캐릭터 이미지를 권장합니다. 완전한 의미 인식과 새로운 3D 모델 생성에는 별도 모델/서비스 연결이 필요합니다.

촬영 사진은 로컬 HumanSeg로 배경을 제거합니다. 분리된 다리 윤곽과 유효한 Pose 랜드마크가 있으면 얼굴·몸통·팔다리 사진을 대응 영역에 부드럽게 혼합하고, 없으면 사람 전체 텍스처를 사용합니다. 부위 판별 역시 윤곽 휴리스틱이며 임의 형체의 해부학적 구조를 보장하지 않습니다. 카메라는 촬영 즉시 종료되고, 닫기/예제 이동 시 대기 촬영과 후속 추론을 취소합니다. 외부로 사진을 전송하지 않습니다.

`npm run build` 후 `node scripts/check-earth-movein.mjs`로 합성 카메라의 입주 흐름, 기본 동물, 이름·대화, 텍스처 편집·되돌리기, 새로고침 후 저장 복원, 회의·음악 버튼을 검사합니다. `node scripts/check-earth-residents.mjs`는 실제 포인터 클릭·드래그·방출과 저장 삭제, 우주선·우주인 공격 및 출발을 검사합니다. 테스트의 HumanSeg/Pose 응답은 대체 데이터이며 실제 인식 품질, 청음 평가 및 모든 플랫폼 검증은 포함하지 않습니다. 개발 서버를 실행하지 않고 로컬 파일을 브라우저에 전달합니다.

- Shampoo: 머리에 기본 생성되는 거품의 표시 지름을 2배로 확대합니다. 거품 개수·캐시·핀치로 만드는 거품은 유지합니다.
- 고무 인간: 실시간 카메라 배경은 원본 좌표에 고정하고, 얼굴 윤곽 마스크를 변형과 함께 이동시켜 잡은 부위가 손 위치까지 윤곽 밖으로 늘어납니다. 양손·스프링 복귀는 유지합니다. 늘어난 얼굴이 덮는 부분 이외의 배경은 변형하지 않습니다. `node scripts/check-rubber-renderer.mjs`는 합성 영상으로 손 위치 대응, 윤곽 밖 확장, 외부 배경 불변, 복귀를 검사합니다. 실제 사람의 카메라 추적 품질을 검증하는 테스트는 아닙니다.
- Aquarium: 크고 작은 단색 열대어에 눈만 남기고 입·볼터치·무늬를 제거했습니다. 반투명 지느러미와 색상별 발광 스프라이트를 캐시해 은은한 광채를 표현하며 시선 모이기·손끝 회피·입 벌림 도망 동작은 유지합니다. `node scripts/check-aquarium-fish.mjs`로 발광·눈·스프라이트 재사용을 검사합니다.
- Effect: 카메라 소스와 손 랜드마크 좌표를 함께 좌우 반전합니다. 업로드 이미지·동영상은 반전하지 않습니다.

### Effect 추가 도구

손 관절점·연결선 표시는 Effect 카메라에서만 그립니다. 좌우 반전 및 화면 비율에 맞춰 투영하며, 손을 놓치면 짧은 유예 후 표시를 지웁니다. lab의 손 뼈대 오버레이는 제거했지만 꽃을 조작하는 손 인식은 유지됩니다. 카메라 시작/중지 버튼은 짧은 폭으로 화면 우측 상단에 고정하며, Earth 입주 대화상자에서는 카메라 영역 내부 우측에 정렬됩니다. `node scripts/check-camera-controls.mjs`는 데스크톱·모바일 레이아웃을 검사합니다.

툴바에서 컬러·흑백을 전환하고 `접기 / 도구 펼치기`로 패널을 접을 수 있습니다. 흑백 변환은 실제 출력 캔버스에 적용되므로 촬영·녹화에도 반영됩니다. 기존 빛 사각형과 ASCII는 제거하고 `Melted Spectrum`과 `열화상`으로 교체했습니다. 전자는 TouchDesigner의 변위·색 채널 분리·블룸 처리 방식을 참고한 브라우저 자체 효과이며 TouchDesigner 런타임을 연결하지 않습니다. 후자는 명암을 차가운/따뜻한 색상으로 매핑하는 시각 효과로 실제 온도 측정이 아닙니다. 기존 부분 효과 창, 컬러/흑백, 촬영·저장, 랜덤 선택은 유지합니다. 정지 사진에서도 멜트가 흐르며 처리 버퍼는 최대 폭 240–360픽셀로 제한합니다.

양손의 엄지·검지로 유효한 창을 새로 만들 때마다 이전과 다른 효과를 고릅니다. 창을 유지하는 동안에는 바뀌지 않으며, 손을 내리거나 창을 닫은 상태가 약 0.45초 지속된 뒤 다시 만들면 새 효과가 선택됩니다. Recolor가 랜덤 선택되면 3~6색만 사용합니다. 기존 2도 표현은 수동 선택에서 유지됩니다. `node scripts/check-travel-effects.mjs`는 합성 카메라·손 좌표로 팔레트, 흑백 픽셀, 패널 접기, 숫자 효과, 새 창 랜덤 선택과 정리를 검증합니다.
